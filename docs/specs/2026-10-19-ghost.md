# Ghost на Hetzner: прямой HTTPS и SSH через Tailscale

## Цель и согласованное изменение
Ghost доступен по https://ghost.dzen.dev на VPS 95.217.219.81 под пользователем deploy за nginx. Административный SSH доступен только через Tailscale. По прямому запросу пользователя Cloudflare Tunnel удалён, HTTPS перенесён на nginx с certbot, публичный сайт использует IPv4. Cloudflare остаётся только DNS-провайдером.

## Схема
Internet IPv4 HTTPS → nginx 0.0.0.0:443 → Ghost 127.0.0.1:2368 → локальный MySQL.

DNS: A ghost.dzen.dev → 95.217.219.81, DNS only, AAAA отсутствует. Порт 80 обслуживает HTTP-01 challenge и перенаправляет остальные запросы на HTTPS. Вход deploy по ключу через Tailscale 100.76.172.36, публичный 22 закрыт. Сертификат Let’s Encrypt обновляется certbot.timer, deploy hook проверяет и перезагружает nginx.

## Ограничения
- Не изменять первое задание и чужие домены/туннели/серверы.
- Не отключать SSH до проверки отдельного deploy-входа через Tailscale.
- По рецепту начальной настройки: deploy/sudo/ключи, отключённые root/password SSH, UFW deny incoming; исключения только публичные 80/443 и SSH через tailscale0.
- Ghost и MySQL остаются на loopback, web IPv6 не публикуется.
- Не оставлять старый Cloudflare ingress, aliases, резервные пути или автоматическое открытие публичного SSH.
- Секреты не попадают в Git/stdout/переписку. Owner test@example.com, пароль в ignored локальном файле, пароль БД только на VPS.
- VPS уже выделен; DNS-настройка и Tailscale approval — явные условия единого скрипта, не автоматизированное платное provisioning/OAuth.
- Скрипт не затирает неизвестные данные/конфигурации; конфликт приводит к явной ошибке.

## Затрагиваемые файлы
- `ghost/deploy.sh`: единственный самостоятельный POSIX sh файл, включает bootstrap пользователей/ключей, установку Tailscale и всего стека, owner setup, TLS и handover на приватный SSH. Нет Python или embedded JavaScript; JSON формируется jq.
- `ghost/scripts/test.sh`, `verify.sh`: shell syntax/ShellCheck/отказ на неверном вводе, реальный DNS/HTTPS/firewall/SSH.
- `ghost/evidence/*`, `ghost/verification.md`, `ghost/README.md`: доказательства, инструкция и ограничения.
- `README.md`, `.gitignore`, `ai/*`: результат сдачи, секреты вне Git, видимый диалог.
- Прежние отдельные Python/Bash helpers и templates удалены: Gist не требует checkout репозитория.

## Примеры
```nginx
listen 0.0.0.0:443 ssl;
ssl_certificate /etc/letsencrypt/live/ghost.dzen.dev/fullchain.pem;
proxy_pass http://127.0.0.1:2368;
proxy_set_header X-Forwarded-Proto https;
```
```bash
certbot certonly --webroot -w /var/www/letsencrypt -d ghost.dzen.dev
ufw allow in on tailscale0 to any port 22 proto tcp
ufw allow 80/tcp
ufw allow 443/tcp
```

## Приёмка и порядок проверки
1. Bash/Python syntax, nginx -t; независимый deploy SSH по Tailscale и подтверждённый fingerprint.
2. A-запись содержит IPv4 VPS, AAAA отсутствует; приложение доступно обычным DNS-запросом без подстановки IP.
3. HTTPS главной/admin возвращает 200 с валидным сертификатом; HTTP перенаправляет на HTTPS; owner setup закрыт.
4. Ghost User=deploy; MySQL/Ghost loopback; публичные 22/2368/3306/8080 недоступны, 80/443 доступны.
5. UFW активен; root/password SSH запрещены; приватный SSH работает.
6. certbot.timer включён, renew --dry-run и deploy hook проходят; nginx/Ghost/MySQL/Tailscale включены в автозапуск.
7. Cloudflare Tunnel и cloudflared полностью удалены для этой установки; чужие туннели не затронуты.
8. Повторный deploy сохраняет данные/owner. Зафиксированы реальные проверки, браузерный скриншот и ограничения, без заявлений о непроверенных пунктах.

Облачная установка сначала выполнена шагами, затем проверены повторные запуски общего скрипта на этом VPS. Полностью unattended fresh install на втором чистом VPS не проверялся. SMTP и внешние backup/restore не входят в текущую поставку.
