# Ghost на Hetzner через Tailscale и Cloudflare Tunnel

## Цель
Работающий Ghost по https://ghost.dzen.dev на выделенном VPS 95.217.219.81, исходники воспроизводимой установки и фактический отчёт в приватном репозитории задания.

## Контекст
- Hetzner VPS 171208001, Ubuntu 26.04.1 LTS, ARM64, 4 ГБ RAM.
- Согласованный рецепт: /Users/xen/Dev/treasure/recipes/ops/new-server.md.
- Пользователь подтвердил переустановку VPS и замену старого SSH host key.
- Ghost owner: test@example.com; пароль генерируется и хранится только вне Git.

## Целевая схема
Internet HTTPS → Cloudflare edge → исходящий cloudflared tunnel → nginx на loopback → Ghost на 127.0.0.1:2368 → локальный MySQL.

Ghost установлен и запущен через systemd под deploy. Административный SSH работает по ключу через Tailscale. После проверки приватного доступа публичный SSH закрывается; nginx, Ghost и MySQL не слушают публичные интерфейсы.

## Ограничения
- Не изменять первое задание, другие домены/туннели, локальную сеть Tailscale и посторонние серверы.
- Не закрывать текущий SSH до проверки отдельного deploy-входа через Tailscale.
- Рецепт адаптируется: публичные 22/80/443 в итоговом firewall не открываются, поскольку трафик идёт через туннели.
- Не публиковать открытый initial owner setup; сначала создать владельца, затем публиковать DNS.
- Сертификат управления Cloudflare остаётся на Mac; сервер получает только credentials одного своего туннеля.
- Секреты не попадают в Git, stdout, журнал установки или копию переписки.
- TLS завершается на Cloudflare; транспорт Cloudflare → cloudflared зашифрован, HTTP допустим только на loopback сервера.

## Порядок
1. Снять состояние, настроить deploy/sudo/ключи и запретить парольный SSH.
2. Установить Tailscale, зарегистрировать устройство в существующей сети, проверить SSH на приватном адресе.
3. Установить Node 22, MySQL, nginx и Ghost CLI, затем Ghost под deploy; создать отдельного DB-пользователя и systemd unit.
4. Создать Ghost owner локальным запросом; проверить health и nginx.
5. Создать отдельный Cloudflare Tunnel и DNS ghost.dzen.dev, проверить HTTPS.
6. Закрыть публичный SSH/firewall, проверить отсутствие публичных портов и сохранение работы сайта/приватного входа.
7. Проверить перезапуск служб/сервера; сохранить скрипты, версии, проверки и ограничения.

## Приёмка
- HTTPS домена отдаёт Ghost без циклов редиректа, admin login доступен, owner setup завершён.
- Ghost systemd активен, User=deploy; файлы/конфигурация доступны только нужным пользователям.
- nginx, Ghost и MySQL слушают loopback; TCP 22 недоступен снаружи для IPv4/IPv6, приватный deploy SSH работает.
- UFW активен, default deny incoming; доступ по SSH разрешён только на tailscale0.
- Парольная SSH-аутентификация и root SSH отключены после проверки deploy.
- cloudflared и tailscaled активны и запускаются при загрузке; после перезапуска сайт и приватный SSH работают.
- Скрипты не затирают неизвестные установки/данные и завершаются явной ошибкой при конфликте.

## Затрагиваемые файлы и границы автоматизации
- `ghost/deploy.sh`: единый запуск через уже подключённый Tailscale, последовательность установки и проверки.
- `ghost/scripts/bootstrap.sh`: первичная учётная запись, ключи, sudo и установка Tailscale; регистрация устройства требует владельца tailnet.
- `ghost/scripts/prerequisites.sh`: ARM64, Node 22, MySQL, nginx, Ghost CLI.
- `ghost/scripts/configure.py`: пароль БД, конфигурация loopback, отказ при конфликте существующих данных.
- `ghost/scripts/claim-owner.py`: создание владельца локальным запросом через SSH; пароль хранится в ignored `.secrets`.
- `ghost/scripts/lockdown.sh`: key-only SSH для deploy, UFW только tailscale0; вызывается через проверенный приватный SSH.
- `ghost/templates/*`: systemd Ghost/cloudflared, nginx, ingress, исправление обнаруженной гонки cloud-init/udev на данном образе.
- `ghost/scripts/verify.py`, `ghost/evidence/*`, `ghost/verification.md`: воспроизводимая проверка, артефакты и фактические ограничения.
- `.gitignore`, `README.md`, `ghost/README.md`, `ai/*`: защита секретов, инструкция сдачи и копия диалога.

Cloudflare account/tunnel/DNS и Tailscale approval являются явными входными условиями скрипта, а не скрытыми предположениями. Платное создание VPS и автоматизация OAuth не входят в скрипт. Реальный туннель/DNS настроены в ходе этой задачи. Fresh-VPS unattended install одним запуском с нуля не проверялся; проверены фактическая установка шагами и повторный запуск общего скрипта на этом сервере.

## Примеры реализации
```ini
[Service]
User=deploy
WorkingDirectory=/var/www/ghost
Environment=NODE_ENV=production
ExecStart=/usr/bin/node /var/www/ghost/current/index.js
```
```nginx
listen 127.0.0.1:8080;
proxy_pass http://127.0.0.1:2368;
proxy_set_header X-Forwarded-Proto https;
```
```bash
ufw default deny incoming
ufw allow in on tailscale0 to any port 22 proto tcp
```

Порядок проверки: bash/Python syntax → отдельный приватный SSH и fingerprint → установка/claim owner → nginx/cloudflared validation → повторный deploy без потери данных → HTTPS/setup/admin/HTTP redirect → внешние TCP probes → reboot → повторная проверка SSH/сервисов/HTTPS. Непроверенные пункты отмечаются отдельно от пройденных.
